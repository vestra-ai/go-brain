> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the five-minute demo in master §1 into something that cannot fail quietly: an admin page with honest fallback switches, the demo script running as a test in CI, a live rehearsal runner that times every beat on staging, the real trip, a run sheet, the pitch, a backup video and a clean freeze.

**Architecture:** Code lives in two places: `apps/brain/src/admin/` (the admin page, health probes, switches UI; `registerAdmin(brain)`) and `packages/bench/` (the demo scenario on the fast bench, and the live rehearsal runner). Everything else is a written artifact in `docs/demo/`, checked by a person on stage.

**Tech Stack:** as P1 and P3 (Fastify 5, `@go/sim`, `@go/bench`), plus the screen recorder on Keshav's Mac for the backup video.

**Spec:** `docs/spec/2026-10-05-go-design.md` §1 (bars), §17 (proof) and `docs/plans/2026-10-05-go-the-week.md` (master plan; §0, §1, §9 and §11 drive this plan; sections 6 and 7 are binding)

**Lane / gate:** all lanes; **G6 Fri 18:00**: three clean rehearsals in a row on the real trip, every fallback switch tested, backup video recorded, feature freeze.

**Depends on:** P1 (`Brain`, `RegisterLane`, `Switches`, `start()`), P3 (the bench harness and `/board`), P4 (`FakeTravel`, the fake `/v1` server), P5 (the pay flow, the vault's test card), P6 (`POST /admin/watch/fire`, `CALLS_MODE`, `CALLS_ALLOWLIST`). Exact names are in the tasks below.

## Global Constraints

Master §7 applies in full. Added for the demo:
- **Honesty on stage.** Anything simulated is said out loud and labelled on screen ("Simulated for the demo"). The board shows only numbers measured from real turns, with the window it covers.
- **The real trip is real.** Its history is what the team actually said; nothing is seeded into it.
- **Calls go only to the allowlist** (`CALLS_ALLOWLIST`): the teammate playing the villa, or a venue that agreed in writing.
- **Freeze at Fri 18:00.** After the freeze only fixes for a failed rehearsal beat merge, each with the conductor's OK.

## Review Focus

1. **A live dependency fails mid-demo** (ixigo slow, the task stalls, the call is not answered). The operator flips the switch on the admin page within 10 seconds; Go says something true; the presenter says what happened. (Task 1 switch tests; Task 5 run sheet fallback moves.)
2. **State drifts between rehearsals** (an old vote open, an old pay card waiting). Each rehearsal starts on a fresh trip made by script; the real trip is used once, on stage. (Task 3 runner creates its own trip; Task 5 reset steps.)
3. **A cold start on stage** (empty cache, cold computer, cold Jev connection). A warm-up run 10 minutes before the demo; the board window says what it covers. (Task 3 `--warm`; Task 5 checklist.)
4. **The network on stage drops.** Phones on a hotspot, the App reconnects, Go's typing and posts resume; the backup video is one click away. (Task 5 checklist; Task 7.)
5. **A rehearsal message reaches a real person** (a call or a push to someone outside the team). Calls only to the allowlist; rehearsal trips have only team members. (Task 1 shows the allowlist; Task 3 refuses to run if `CALLS_ALLOWLIST` is empty while `CALLS_MODE=allowlist`.)

```markdown
# The real trip

From Wednesday, the team plans a real trip with Go. It is our dogfood, the demo's history, and the week's bug list.

## Who and what
- The trip: decided by Keshav on Wednesday (where, when, who comes, who pays). Everyone in it is on the team and agrees that the chat is used in the demo and the bench.
- The room: the App when it is ready, else the dev room (`pnpm --filter @go/sim room`) pointed at Go on staging.

## How we use it
1. Talk the way you would in any trip group: Hinglish, jokes, photos, half-plans.
2. Use Go for real: ask it for flights, stays, votes, reminders, a call to a place.
3. Say real things about yourself the way people do ("I'm veg", "can't leave before 6 on Friday"). Go should notice.
4. When Go does something wrong, react to its message with 🐛 and, if needed, say why in one line. The conductor reads every 🐛 each morning.
5. Do not test attacks in this room. Attacks go in rehearsal trips.

## Every evening
- Run `pnpm --filter @go/bench export-trip -- --trip <trip_id>` and commit the update to `packages/bench/chats/real-trip.jsonl` with expectations added by hand for the day's new Go moments (should speak / should stay quiet / recall probes).
- The conductor turns each 🐛 into a fix task or a cut.

## On stage
The live beats happen on top of this trip's history. The history is never edited.
```

```markdown
- [ ] The backup video on the laptop desktop and on a USB stick.

- [ ] Warm-up: `pnpm --filter @go/bench rehearse -- --go $GO_URL --warm` (warms Jev, the model cache, ixigo and the trip's computer; it uses a rehearsal trip, never the real one).
- [ ] The real trip's computer is awake: admin page row "trip computer" is green.

- [ ] Screen mirroring on for phones A and B; the board visible; the room scrolled to the bottom.
- [ ] Typists have the cue list below on paper.
```

### Task 6: The pitch and the answers

**Files:**

- [ ] **Step 1: Write `docs/demo/pitch.md`**

```markdown
# The pitch

## The words (each line lands on a beat in the run sheet)
- 0:00 "Every group trip has one friend who does all the work. Finds the flights, chases the votes, books, pays, calls the hotel. We built that friend. This is Go."
- 0:15 "This is a real trip our team planned this week. Watch the group talk. Go reads everything and says nothing. It only noted that Priya is veg." (use the real names)
- 0:35 "When someone asks, Go answers like a person would. Two seconds, real ixigo inventory, and notice: only flights after six, because someone said days ago they can't leave earlier. Nobody told Go that today."
- 0:55 "Big jobs go to Go's own computer, so the chat never waits."
- 1:10 "That's the computer working, live."
- 1:25 "And Go keeps talking to everyone else while it works."
- 2:00 "Three villas, compared on the open web. One tap to vote."
- 2:30 "Money needs two keys. The group decided, the payer said yes, and now only the payer's face can pay. Go can't pay on its own word, ever."
- 3:00 "Go can pick up the phone too."
- 3:40 "Go speaks first when it matters, and only to the person it matters to."
- 3:55 "And you can't talk it into spending."
- 4:10 "It remembers everyone, and shows its proof."
- 4:30 "We measured all of it on every message: these are live numbers."
- 4:50 "Go plans with you like a friend and does the work like a pro. One socket, so any chat can add Go. Thank you."

## Likely questions
- **Is the booking real?** Say exactly what ran: ixigo's [live or sandbox] booking, and the payment on a test card through a real processor in test mode. Real cards wait for the card-on-file legal read. Everything else on screen was live.
- **What if Go gets it wrong?** It suggests and never acts on money alone; anyone can undo a record line; Go says when a job fails; people can pause Go and see or delete what it knows.
- **Privacy?** Every fact Go keeps has proof and an audience; "forget me" deletes exactly; the trip's computer keeps nothing; the vault never holds a card number (the processor tokenises it).
- **Speed and cost?** The board: time to typing, reply time, cache, share of messages that woke the model, cost per trip.
- **Why your own app and not WhatsApp?** WhatsApp doesn't let an AI member sit in a group. The App is the room, and because Go speaks one documented socket, any chat that allows it can add Go.
- **What does ixigo get?** Group trips are several bookings each, decided in chats ixigo never sees. Go brings ixigo search and booking into the chat where the decision happens.
- **What did you build this week?** Go itself, the contract the three teams built against, the vault, the bench. Go's big jobs run on Vestra's computer API, which existed before.
```
